## Riesgos que ahora tienen regresión automática

- El cliente no puede enviar el monto efectivo de una seña o compra: se deriva desde orden, presupuesto o catálogo.
- Un técnico no puede crear pagos ni solicitudes como cliente.
- Una dirección o presupuesto de otra orden/cliente no puede reutilizarse.
- Un error de Mercado Pago deja la transacción o borrador cancelado.
- Un webhook repetido conserva idempotencia.
- Presupuestos borrador, vencidos, rechazados o aceptados exponen únicamente las acciones permitidas.
- RLS de conversaciones, notificaciones, reclamos, liquidaciones, técnicos, configuración y metas se valida en el proyecto live dentro de transacciones con `ROLLBACK`.

## CI

El workflow bloquea lint, build, Vitest con cobertura y reconstrucción de migraciones desde cero. E2E bloquea cuando están configuradas `VITE_SUPABASE_URL` y `VITE_SUPABASE_ANON_KEY`; los escenarios autenticados requieren además secretos `E2E_*` y, para fixtures, `SUPABASE_SERVICE_ROLE_KEY`. Ningún valor secreto se incluye en el repositorio ni en este informe.
